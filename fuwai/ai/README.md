# 成员 3：ASR 与 AI MVP 规范

## 1. 当前目标

20 天内完成一个可联调的第一阶段 MVP：

```text
音频上传
-> 服务端中文语音转写
-> 用户确认转写文字
-> 生成标题、忠实摘要、标签和回复建议
-> 返回结构化 JSON
```

本阶段优先保证稳定、可验证和可解释，不追求 AI 功能数量。

## 2. 本阶段交付范围

### ASR

- 统一处理 Apple Watch 和 T5AI 挂件上传的音频；
- 返回中文转写文本、语言、处理状态和错误码；
- 支持空音频、格式错误、超时和服务失败的明确错误结果；
- ASR 失败不能阻止原声保存，调用方必须可以重试；
- 原始音频只用于播放、ASR 和日记保存，默认不直接提供给 AI 模型。

### 单条生活瞬间 AI

输入必须来自用户确认后的真实转写文字，并可包含：

- `event_id`；
- `transcript`；
- `recorded_at`；
- 用户主动提供的上下文；
- 用户是否授权 AI 使用该文字。

输出第一阶段固定包含：

- `title`：简短、忠实的标题；
- `summary`：不增加事实的摘要；
- `tags`：少量描述性标签；
- `suggested_replies`：可选回复草稿，不自动发送；
- `safety_flags`：安全或需要人工确认的标记；
- `schema_version`：当前为 `1`。

## 3. 明确禁止的行为

AI 不得：

- 根据 BPM 推断悲伤、紧张、兴奋等具体情绪；
- 诊断心理或身体疾病；
- 评价情侣关系质量、忠诚度或健康程度；
- 编造转写文字中不存在的人、事、时间、地点或记忆；
- 把不确定内容改写成确定事实；
- 未经用户确认自动发送回复或通知伴侣；
- 根据心率向伴侣自动报告异常状态；
- 读取未获得用户授权的转写内容；
- 默认分析原始录音中的额外信息或背景声音。

## 4. 忠实度规则

- 保留原文的主要事实和说话者意图；
- 不擅自补充原因、情绪、关系判断或行动建议；
- 内容模糊时使用中性表达，例如“提到一件学习相关的事情”；
- 内容为空、无法识别或主要是噪声时，不生成虚构摘要；
- 回复建议应使用可能性表达，不代表对方真实意愿；
- 标签只描述文本中明确出现的主题，不从 BPM 推导标签。

## 5. 失败与降级策略

| 场景 | 处理方式 |
|---|---|
| ASR 暂时失败 | 返回 `failed` 和错误码，允许重试 |
| 音频格式不支持 | 返回 `invalid_audio`，不调用 AI |
| 转写为空 | 保留原声，返回空文本状态，不生成虚构内容 |
| AI 超时 | 返回可重试状态，不改变原始转写 |
| AI 输出不是合法 JSON | 校验失败并重试一次，仍失败则返回结构化错误 |
| 检测到敏感或高风险内容 | 保留原意，设置 `safety_flags`，交由用户确认 |

## 6. 与成员 2 的责任边界

成员 3 负责：

- ASR provider 适配和统一结果；
- AI Prompt、模型调用和结构化输出；
- 安全规则、评估集和评估报告；
- 提供稳定的请求/响应 Schema 和集成说明。

成员 2 负责：

- 音频接收、私有存储和权限校验；
- 任务状态持久化、重试调度和 API 网关；
- AI 结果入库和向客户端返回；
- 不把未授权文字发送给成员 3 的服务。

## 7. 待确认的调用契约

AI 相关接口由成员 2 的后端统一编排；本目录当前已经实现并可独立部署的接口是：

```text
GET  /healthz
POST /internal/ai/asr
```

`/internal/ai/asr` 是供成员 2 后端调用的内部接口。`/ai/moment` 的 Prompt、模型调用和结构化输出属于后续 AI 模块，本服务当前不提供该路由。

详细字段在第 2 天固化到 `ai/contracts/`。在接口冻结前，成员 2 应确认：

1. 音频上传格式和最大大小；
2. 是否采用同步调用或异步任务；
3. 用户授权字段名称和校验位置；
4. 失败重试次数和超时；
5. AI 结果保存所需的 `event_id`。

## 8. 第一阶段完成定义

- 两种来源的中文测试音频都能返回统一 ASR 结果；
- 用户确认后的文字能生成合法的单条瞬间 JSON；
- 至少 10 条正常、模糊、敏感、空内容用例通过评估；
- 能证明摘要没有编造事实，且没有根据 BPM 推断情绪；
- 成员 2 可以根据 Schema 调用服务并处理失败重试；
- 仓库中不包含 API Key、真实录音或真实用户关系数据。

## 9. 第 4～5 天 ASR 测试

当前正式方案：讯飞“录音文件转写大模型”。

`ai/asr_iflytek.py` 是实时语音转写 WebSocket 的旧参考实现，不能直接作为正式的录音文件转写实现。

统一结果入口：`ai/asr_service.py`。它将讯飞错误转换为第 2 天定义的 `asr-response.schema.json` 格式。

安装依赖：

```powershell
pip install -r ai/requirements.txt
```

准备 `.env`（由 `.env.example` 复制），填写讯飞 `APPID`、`APIKey`、`APISecret`。然后使用 16 kHz、16 bit、单声道 WAV 测试：

```powershell
python ai/asr_service.py sample.wav --event-id event_001 --source watch --consent
```

实现细节、字段映射和结果解析见 `ai/contracts/iflytek-file-asr.md`。客户端已固定使用官方 `/v2/upload`、`/v2/getResult` 两步流程；不能把实时 WebSocket 地址或参数用于该产品。
