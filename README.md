# 共在 Gongzai AI Empathy

> 面向异地情侣的 AI 生活瞬间共感与保存系统：Apple Watch App + iPhone App + Tuya T5AI 实体挂件 + FastAPI 后端。

## 项目简介

“共在”希望降低异地情侣分享细小生活瞬间的表达成本。系统把一段真实心率、本人原声、转写文字和对方回应组织成一个“生活瞬间”，并在不同终端采用不同表达方式：

- **Apple Watch：文字 + 心率触觉**；
- **实体挂件：本人原声 + 心率灯光**；
- **AI：整理、检索和回顾双方主动保存的真实记录**。

项目不通过心率判断具体情绪，不进行疾病诊断，不允许伴侣随时查询对方状态，也不替用户自动发送内容。

## 已确认的产品决策

- 挂件使用 LED 表现心率，不安装振动马达；
- Apple Watch 使用系统触觉表现心率；
- 挂件包含 LED、扬声器、按钮和麦克风；
- 麦克风仅在用户按住按钮时录制回复，不持续监听；
- 挂件通过 Wi-Fi 连接 Tuya 云，Bluetooth LE 用于配网、绑定和本地维护；
- Apple Watch 与挂件的录音统一上传服务器进行语音转文字；
- 原声作为日记和回忆内容长期保存，转写文字可在用户授权后提供给 AI；
- 原声和转写分离：挂件播放原声，Apple Watch 展示文字；
- AI 功能尽量丰富，但所有输出必须基于真实记录并受安全边界约束；
- 数据库归成员 2；成员 4 不承担技术开发。

## 目标用户与边界

- 首要用户为处于异地状态、希望保持轻量日常连接的情侣；
- 适合分享“不值得专门发消息，但希望对方知道”的生活瞬间；
- 心率默认不共享，每次由本人主动发起；
- 不允许接收方主动查询发送方的实时心率；
- 不进行心理治疗、关系评价、疾病判断或伴侣监控；
- 心率、灯光、触觉均为生活情境线索，不是通用情绪编码。

## 核心功能

### 1. 记录这一刻

- Apple Watch 主动采集 10～15 秒心率；
- 用户录制 10～20 秒原声；
- 服务器对原声进行语音转文字；
- 用户检查文字并确认分享；
- 一次生活瞬间同时保存 BPM、原声、文字和时间。

### 2. 感受这一刻

- Apple Watch 展示转写文字，并按 BPM 播放系统触觉；
- T5AI 挂件通过 LED 柔和脉动呈现 BPM；
- 挂件扬声器播放发送者本人原声；
- 灯光只表达设备状态和心率节奏，不预设“某种颜色等于某种情绪”。

### 3. 回应这一刻

- 轻触挂件表示“已收到”；
- 按住按钮启动麦克风录音，松开结束；
- 挂件通过 Wi-Fi 上传回复原声；
- 服务器完成回复原声转写，Apple Watch 展示回复文字；
- 挂件不配置外挂 ASR 模块，所有自由口述和回复均由服务器统一转写。

### 4. 记住这一刻

- AI 生成忠于原意的标题、摘要和标签；
- AI 提供可选择的回复建议；
- 系统形成共同时间线；
- AI 支持周报、月报、纪念日回顾和真实记忆检索；
- 用户可删除片段、撤回授权和解除关系绑定。

## 通信与数据约定

### 网络

- 挂件主链路：2.4 GHz Wi-Fi → Tuya 云；
- BLE：首次配网、设备绑定和近距离维护；
- BLE 不作为异地消息的常规网关；
- `WatchConnectivity` 只连接同一用户配对的 Watch 和 iPhone。

### 事件结构

```json
{
  "event_id": "uuid",
  "sender_id": "user_a",
  "receiver_id": "user_b",
  "average_bpm": 82,
  "beat_intervals_ms": [730, 745, 720],
  "transcript": "今天答辩终于结束了。",
  "voice_asset_id": "voice_uuid",
  "recorded_at": "2026-07-29T15:30:00+08:00",
  "status": "created",
  "schema_version": 1
}
```

状态统一为：

```text
created → uploaded → delivered → played → acknowledged → replied
                                                    └→ failed
```

### 建议 DP

| DP | 类型 | 方向 | 用途 |
|---|---|---|---|
| `event_id` | string | 云→设备 | 事件唯一标识 |
| `heartbeat_bpm` | value | 云→设备 | LED 脉动频率 |
| `light_mode` | enum | 云→设备 | idle / incoming / heartbeat / recording |
| `voice_task` | string/raw | 云→设备 | 原声播放任务标识，不传大文件本体 |
| `touch_event` | enum | 设备→云 | tap / long_press |
| `record_state` | enum | 双向 | idle / recording / uploading / failed |
| `acknowledged` | bool | 设备→云 | 已收到 |
| `online_state` | bool | 设备→云 | 在线状态 |

音频文件不通过 DP 传输；DP 只传任务或资源标识。

## 分支、提交、Issue 与 PR

- `main` 始终保持可构建、可演示，不直接提交；
- 每个 Issue 使用独立分支；
- 分支示例：`feature/watch-heart-rate`、`feature/pendant-audio`、`feature/backend-moment-api`；
- 提交格式：`<type>(<scope>): <summary>`；
- 示例：`feat(pendant): add button-controlled voice reply`；
- PR 必须关联 Issue、说明验证方法并由至少一名非作者 Review；
- API、DP、数据库或 AI Schema 变化必须同步更新文档；
- 接口破坏性变更必须提高 `schema_version`。

## 密钥与隐私规则

禁止提交：

- Tuya Access ID / Secret；
- 设备 UUID、AuthKey 和授权码；
- AI API Key；
- 数据库密码和 `.env`；
- Apple 证书、私钥和配置文件；
- 真实用户心率、语音、照片和关系数据。

基本规则：

- 原始录音由服务端 ASR 使用并进入双方日记；AI 默认读取转写文字，不直接分析原始录音；
- 心率和原声必须由本人主动发送；
- 麦克风只在按住按钮时启用，并提供明确灯光提示；
- 原声使用私有存储和短期地址；
- 原声需要在服务器解密后完成 ASR，因此当前架构不宣称端到端加密；使用 TLS、私有存储、静态加密和短期访问地址保护数据；
- 解绑后停止数据互通并撤销设备权限；
- 测试使用合成或匿名数据。
