# 共在技术路线

## 1. 当前目标

第一版围绕一个完整生活瞬间闭环展开：

```text
发送者记录原声和心率
→ 服务器生成可确认文字
→ 服务器创建生活瞬间
→ 挂件播放原声并以灯光表现心率
→ 接收者按住挂件录制回复
→ 发送方 Watch 收到回复文字
→ AI 整理为双方共同记忆
```

## 2. 终端表达分工

| 终端 | 接收内容 | 输出方式 |
|---|---|---|
| Apple Watch | 转写文字、平均 BPM、状态 | 文字、系统触觉 |
| T5AI 挂件 | 原声、平均 BPM、事件状态 | 扬声器、LED、触摸 |
| iPhone | 原声、文字、完整事件 | 确认、管理、时间线 |

## 3. Apple 端路线

### 3.1 心率

- 使用 HealthKit；
- 用户主动采集 10～15 秒；
- 第一版保存平均 BPM；
- 后续根据可用接口增加逐拍间隔；
- 不持续后台监测，不自动发送。

### 3.2 原声与转写

目标是用户只说一次，同时得到：

```text
原始音频 → 挂件播放
转写文字 → Watch 展示和 AI 整理
```

第一周分别验证：

1. Watch 录音文件传给 iPhone；
2. iPhone 将录音上传 FastAPI；
3. 服务端 ASR 返回中文转写；
4. iPhone 将确认后的文字与心率创建为一个生活瞬间。

所有终端录音统一由服务器转写，不再采用端侧 ASR 作为主路线。

## 4. 挂件路线

### 4.1 本地硬件

- T5AI-Board；
- LED 灯环或柔光 LED；
- 扬声器；
- 麦克风；
- 录音按钮；
- 触摸模块；
- 第一版 USB 供电。

### 4.2 本地状态机

```text
IDLE
  ├─ 收到事件 → INCOMING
  ├─ 轻触 → ACKNOWLEDGED
  └─ 按住按钮 → RECORDING

INCOMING
  ├─ LED 心率脉动
  ├─ 播放原声 → PLAYED
  └─ 失败 → ERROR

RECORDING
  ├─ 松开按钮 → UPLOADING
  ├─ 超时 → AUTO_STOP
  └─ 上传失败 → RETRYABLE_ERROR
```

### 4.3 灯光

基础间隔：

```text
interval_ms = 60000 / BPM
```

单次脉冲采用快速亮起、缓慢熄灭，不使用刺眼的硬闪烁。灯光只表示节奏和状态。

### 4.4 麦克风

- 默认关闭；
- 按住按钮才开始录制；
- 录音期间显示明确灯光；
- 松开按钮立即结束；
- 设置最长录制时长；
- 失败时不得显示“发送成功”。

### 4.5 外挂 ASR

不用于自由口述转写。后续只考虑本地固定命令：

- 播放；
- 回复；
- 取消；
- 再听一次。

第一周不接入外挂 ASR，避免阻塞灯光、播放和录音主链路。

## 5. 网络路线

### 5.1 挂件联网

- Wi-Fi：Tuya 云主链路；
- BLE：配网、绑定、本地设置和维护；
- 不把 iPhone 作为长期 BLE 网关；
- 离线时服务器保存待处理事件，恢复后重新同步。

### 5.2 音频

- 音频不通过 DP 传输；
- 后端保存私有音频对象；
- Tuya DP 仅传 `event_id` 或 `voice_task`；
- 挂件根据任务取得可播放资源；
- 原声需要由服务端 ASR 读取，因此当前架构不宣称端到端加密；
- 使用 TLS、私有对象存储、静态加密、权限校验和短期地址保护原声。

## 6. 后端与数据库

全部由成员 2 负责。

### 6.1 核心接口

```text
POST /api/moments
GET  /api/moments/{event_id}
POST /api/moments/{event_id}/acknowledge
POST /api/moments/{event_id}/reply
POST /api/voice-assets
GET  /api/timeline
POST /api/devices/bind
```

### 6.2 核心数据表

```text
users
relationships
devices
moments
heartbeat_records
voice_assets
responses
ai_results
permissions
```

### 6.3 状态与幂等

每个事件必须有唯一 `event_id`。服务器必须保证重复上传、重复下发和重复设备上报不会创建多条记录。

## 7. AI 路线

成员 3 提供服务端 ASR 与独立 AI 工作流，成员 2 负责 API、调度和保存结果。

### 7.0 服务端 ASR

- 接收 Apple Watch 与挂件录音；
- 统一返回原始转写、语言、状态和错误码；
- 原始音频作为日记与回忆资产保存；
- 转写文字经用户授权后提供给后续 AI 工作流；
- ASR 失败不得阻止用户保存原声，但应允许重试。

### 7.1 单个瞬间

输入：用户确认后的文字、时间及用户主动提供的上下文。

输出：

```json
{
  "title": "答辩结束后的松一口气",
  "summary": "今天答辩有些混乱，但结束后轻松了很多。",
  "tags": ["学习", "答辩", "分享"],
  "suggested_replies": [
    "辛苦了，结束了就好。",
    "晚上有空的话，我们聊一会儿。"
  ],
  "safety_flags": [],
  "schema_version": 1
}
```

### 7.2 长期功能

- 时间线整理；
- 周报、月报；
- 纪念日回顾；
- 语义检索真实片段；
- 根据用户选择生成回复草稿；
- 提醒候选，但不自动发送。

### 7.3 禁止事项

- 根据 BPM 判断悲伤、紧张或兴奋；
- 诊断心理或身体疾病；
- 评价关系健康程度；
- 编造未发生的共同记忆；
- 未经确认发送内容；
- 向伴侣自动报告状态异常。

## 8. 第一周技术验收

### 成员 1

- Watch 真机取得心率并传给 iPhone；
- 验证 Watch 原声录制并传给 iPhone；
- T5AI 完成 LED、扬声器、按钮录音三个本地实验。

### 成员 2

- FastAPI 与数据库运行；
- 一条 `moment` 可创建、保存和查询；
- 音频可私有上传；
- Tuya 虚拟设备收到 BPM 指令。

### 成员 3

- 服务端 ASR 对 Watch 与挂件测试音频返回统一结果；
- 对样例文字输出标题、摘要、标签、回复建议；
- 输出合法 JSON；
- 至少 10 条测试用例验证忠实度和安全边界。

## 9. 产品形态与比赛范围

- 最终形态：两人各有 Apple Watch、iPhone App 和挂件，系统对称；
- 比赛形态：先用一组 Watch/iPhone 和一个挂件验证非对称闭环；
- 原声：保存进入日记和回忆；
- ASR：所有端统一上传服务器转写；
- AI：允许使用转写文字，原始音频默认只供播放、ASR和日记保存。
